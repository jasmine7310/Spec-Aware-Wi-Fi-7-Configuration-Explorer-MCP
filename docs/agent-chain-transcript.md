**Claude:**

It gets pruned at **P1** with status `SPEC_RULE_VIOLATION`. Two modeled rules reject it, and both come from the AP MLD's links using different AKMs: link 0 uses `SAE-EXT-KEY` and link 1 uses `OWE`.

### 1. `SEC.MLD_COMMON_SUITES`: the links share no AKM
- **Rule:** every AP link must use the same pairwise cipher, and the links' AKM lists must have at least one AKM in common.
- **Here:** `['SAE-EXT-KEY']` and `['OWE']` have nothing in common.
- **Source:** IEEE 802.11be-2024 §12.6.2 "RSNA selection", PDF p. 411 (printed 410), a **shall**. The WFA WPA3 guide §3.1.4.1 (p. 28) repeats it, but that's a NOTE (guidance), not the rule's basis.
- **Experimental validation:** `cited_runs_only`. Runs 1793897820 and 1794875139 are cited, but no committed run breaks this rule.

### 2. `SEC.MLD_SAME_RSNXE`: the links advertise different RSNXEs
- **Rule:** once any link includes an RSNXE, every link must advertise the same one.
- **Here:** `SAE-EXT-KEY` makes hostapd set the SAE hash-to-element bit on link 0. Link 1 (OWE only) sets no bits, so it sends no RSNXE at all.
- **Sources:** 802.11be-2024 §12.6.2, PDF p. 411, a **shall**. Michelle chose the strict reading of this clause in #95. The hostap code at the pinned commit confirms the behavior: `src/ap/wpa_auth_ie.c:549-557` (`rsnxe_capab()`) and `:601-611` (`wpa_write_rsnxe()`).
- **Experimental validation:** `broken_in_a_run`. The labeled negative experiment `runs/experiments/1794875139` breaks this rule, and the hostap test still PASSed there. So hostapd at the pinned commit accepts this setup; the pruning comes from the spec rule, not from the implementation refusing it.

### The fix: one change
`permitted_alternatives` (up to 1 change) found exactly one alternative that passes the modeled rules: set link 1's AKM to `SAE-EXT-KEY`, so both links use `["SAE-EXT-KEY"]`. That alternative is **P2 `SUPPORTED`**. It has already run as runs 1793897820, 1793897968 and 1793898029, so you can rerun it with `run_candidate`.

Passing the modeled rules doesn't mean it fully complies with 802.11be; it only means none of the rules we've modeled reject it.

If you want the OWE link kept, the candidate is outside the legal space as modeled. You could only run it as a labeled negative experiment, which is what 1794875139 already is.
