**Claude:**

The candidate is **pruned at P1** with status `SPEC_RULE_VIOLATION`. The two AP links advertise different security setups: link 0 uses `SAE-EXT-KEY` and link 1 uses `OWE`. That breaks two modeled rules.

**1. `SEC.MLD_COMMON_SUITES`**: the links of an AP MLD must share at least one AKM.
- **What's wrong:** link 0 offers `['SAE-EXT-KEY']` and link 1 offers `['OWE']`, so they have no AKM in common.
- **Source:** IEEE 802.11be-2024 §12.6.2 "RSNA selection", PDF p. 411, a **shall** clause. The links' RSNEs must match apart from the AKM Suite List and MFPR, and at least one AKM must be shared. The WFA WPA3 guide §3.1.4.1 says the same, but only as guidance in a NOTE.
- **Experimental validation:** only cited runs (`1793897820`, `1794875139`). No committed run breaks this rule.

**2. `SEC.MLD_SAME_RSNXE`**: every link of the AP MLD must advertise the same RSNXE.
- **What's wrong:** `SAE-EXT-KEY` makes hostapd set the SAE hash-to-element bit in link 0's RSNXE. Link 1 is OWE only, so it advertises no RSNXE at all. hostapd builds each link's RSNXE from that link's own AKMs (`src/ap/wpa_auth_ie.c:549-557` and `601-611` at the pinned commit).
- **Source:** the same §12.6.2 shall clause. Michelle chose the strict reading in #95: once any link includes an RSNXE, every link must advertise the same one.
- **Experimental validation:** `runs/experiments/1794875139` breaks this rule, and hostapd still **accepted** it (explorer_candidate PASS). So the implementation doesn't enforce this rule. That run is a labeled negative experiment, not evidence that the setup is legal.

Neither rule is encoded in ConfigSpace; both are P1-only checks. In the campaign space every link gets the same AKM, so the planner never generates a candidate like this one.

**Nearest permitted alternative:** I asked for alternatives that change one dimension. Of the 14 candidates considered, only one passes the modeled rules: set link 1's AKM to `SAE-EXT-KEY` as well, keeping channels 1 and 6 and client beacon protection. It is P2 `SUPPORTED` and has already run exactly as shown in runs `1793897820`, `1793897968` and `1793898029`.

Passing the modeled rules only means no modeled rule objects. It doesn't mean the candidate fully complies with 802.11be.
